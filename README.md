# CookBook

Україномовна інтерактивна книга рецептів у форматі PWA (Progressive Web App) для мультиварки **Ninja Foodi SmartLid OL650EU**. Працює офлайн, встановлюється на телефон чи комп'ютер і не потребує реєстрації.

> ⚠️ **Застереження.** Застосунок не замінює офіційну інструкцію до мультиварки. Перед готуванням під тиском завжди перевіряйте за інструкцією мінімальний рівень рідини (не менше 250 мл), лінію PRESSURE MAX, правило «не більше половини чаші» для рису та продуктів, що набухають, і положення клапана (SEAL / VENT).

## Можливості

- Головна сторінка: пошук (за назвою, інгредієнтом, тегом, категорією), картки категорій, блоки «Обрані рецепти» та «Нещодавно переглянуті».
- Сторінка рецепта:
  - час і кількість порцій;
  - перемикач порцій з автоматичним перерахунком інгредієнтів;
  - список інгредієнтів, у якому можна позначати вже підготовлене;
  - покрокова інструкція з окремим блоком параметрів мультиварки (режим, тиск або рівень, час, клапан);
  - поради;
  - кнопка «Додати в обране».
- Світла й темна теми. За замовчуванням береться системна тема, вибір запам'ятовується.
- Кнопка «Не вимикати екран» (Screen Wake Lock API) у браузерах, які її підтримують.
- Власні рецепти: кнопка «Додати рецепт». Вони зберігаються лише в цьому браузері.
- Кнопка «Скопіювати до книги» у власних рецептах: готує pull request з рецептом у репозиторій (див. [нижче](#скопіювати-до-книги-pull-request)).
- Повна робота з клавіатури, видимий фокус, `prefers-reduced-motion`, кнопки щонайменше 44×44 px.
- Офлайн-режим після першого відкриття.

## Структура

```
CookBook/
├── index.html              # розмітка всіх екранів
├── manifest.json           # Web App Manifest (відносні шляхи)
├── service-worker.js       # офлайн-кеш (CACHE_VERSION)
├── css/styles.css
├── fonts/                  # рукописний шрифт Caveat (кирилиця + латиниця) та його ліцензія OFL.txt
├── js/
│   ├── app.js              # точка входу: маршрутизація (#/, #/recipe/<id>, #/category/<id>), SW
│   ├── data.js             # завантаження та нормалізація data/recipes.json
│   ├── storage.js          # localStorage: обране, нещодавні, тема, позначки, власні рецепти
│   ├── theme.js, theme-init.js
│   ├── components.js       # картки, порожні стани
│   ├── add-recipe.js       # форма «Додати рецепт»
│   ├── contribute.js       # «Скопіювати до книги»: JSON рецепта і посилання на GitHub (GITHUB_REPO)
│   ├── wakelock.js
│   ├── utils.js
│   └── views/home.js, views/recipe.js
├── data/
│   ├── meta.json           # schemaVersion, device, категорії (джерело)
│   ├── recipes/<id>.json   # один файл = один рецепт (джерело)
│   └── recipes.json        # ЗГЕНЕРОВАНИЙ файл, який читає застосунок. Вручну не редагувати
├── tools/build_recipes.py  # перевірка джерел і збирання data/recipes.json
├── .github/workflows/recipes.yml  # CI: перевірка PR і автоматичне збирання
├── icons/                  # icon.svg, icon-maskable.svg, icon-192.png, icon-512.png, icon-maskable-512.png
├── images/                 # SVG-ілюстрації рецептів і заглушка
└── docs/                   # вихідні матеріали (інструкція OL650EU, таблиця режимів, рецепт). Не змінювати!
```

Для запуску застосунку збирати нічого не потрібно: `data/recipes.json` лежить у репозиторії. Node.js і сторонні бібліотеки не використовуються. Python потрібен лише для локального перезбирання `recipes.json` (необов'язково, GitHub Actions робить це сам).

## Запуск локально

ES-модулі та Service Worker **не працюють через `file://`**, тому застосунок треба відкривати через локальний вебсервер.

**Варіант 1. Python** (з кореня репозиторію):

```powershell
python -m http.server 8000
```

Відкрийте <http://localhost:8000/>.

**Варіант 2. VS Code + Live Server.** Встановіть розширення Live Server і натисніть **Go Live** у рядку стану.

**Перевірка роботи з підшляху** (як на GitHub Pages). Запустіть сервер із **батьківської** папки й відкрийте `http://localhost:8000/CookBook/`:

```powershell
cd ..
python -m http.server 8000
```

> Якщо після змін бачите стару версію, у DevTools → Application → Service Workers натисніть **Unregister** (або увімкніть **Update on reload**) і оновіть сторінку.

## Як додати рецепт

Кожен рецепт зберігається в окремому файлі `data/recipes/<id>.json`, категорії — у `data/meta.json`. З них скрипт `tools/build_recipes.py` збирає єдиний `data/recipes.json`, який читає застосунок. Окремі файли потрібні, щоб pull request-и з різними рецептами не конфліктували між собою.

1. Створіть файл `data/recipes/<id>.json` з одним об'єктом рецепта за схемою нижче. `id` у файлі має збігатися з назвою файлу і містити лише `a-z`, `0-9` та `-` (наприклад, `borshch`), бо він потрапляє в адресу `#/recipe/borshch`.
2. Технічні дані (режим, тиск, температура, час) беріть **лише** з інструкції в `docs/` або з перевіреного рецепта. Якщо параметр не підтверджено, поставте в кроці `"verified": false`. Поле `verified` застосунок не показує, воно лише для внутрішньої перевірки даних.
3. За бажанням додайте SVG-ілюстрацію в `images/` і вкажіть відносний шлях у полі `image`. Зовнішні посилання (`https://…`) та чужі фото використовувати не можна.
4. Запуште зміни в `develop` або `main`. GitHub Actions перевірить файли, перезбере `data/recipes.json` і закомітить його в ту саму гілку (не забудьте потім зробити `git pull`).
5. Щоб побачити рецепт локально до пушу, зберіть файл самостійно (потрібен Python 3):

   ```powershell
   python tools/build_recipes.py          # перевірити і записати data/recipes.json
   python tools/build_recipes.py --check  # лише перевірити
   ```

### Скопіювати до книги (pull request)

Рецепт, створений у застосунку через «Додати рецепт», можна запропонувати до спільної книги без жодних токенів:

1. На сторінці власного рецепта натисніть **«Скопіювати до книги»**. JSON рецепта копіюється в буфер обміну.
2. Натисніть **«Відкрити GitHub»**. Відкриється сторінка створення файлу `data/recipes/<id>.json`, зазвичай вже заповнена (для дуже великих рецептів текст треба вставити вручну).
3. **Commit changes… → Propose changes → Create pull request.** Учасники без прав на запис автоматично працюють через fork.
4. Власник перевіряє PR і зливає його. Після цього локальна копія рецепта автоматично ховається, бо в книзі з'являється рецепт з тим самим `id`.

У згенерованому JSON кроки з параметрами мультиварки (режим, тиск, температура, клапан) завжди мають `"verified": false`. Перед злиттям звірте їх з інструкцією в `docs/` і за потреби змініть на `true`.

Репозиторій і гілка задаються константою `GITHUB_REPO` у `js/contribute.js`. Під час розробки там `develop`. Перед перенесенням у `main` змініть на `main` (і збільште `CACHE_VERSION`).

**Захист репозиторію.** Workflow `.github/workflows/recipes.yml` для кожного PR у `main` або `develop`:

- `validate` — перевіряє всі джерельні файли (`build_recipes.py --check`): валідний JSON, `id` = назва файлу, існуюча категорія, тільки відомі поля, `image` — лише локальний файл;
- `fork-guard` — для PR з fork-ів дозволяє змінювати лише `data/recipes/<id>.json`.

Одноразове налаштування на GitHub:

1. **Settings → Actions → General → Fork pull request workflows** → *Require approval for all external contributors*. Без цього автор PR може змінити сам workflow.
2. **Settings → Rules → Rulesets → New branch ruleset** для `main` і `develop`: *Require status checks to pass* (`validate`, `fork-guard`), *Block force pushes*. Якщо увімкнете *Require a pull request before merging*, додайте в *Bypass list* себе й GitHub Actions, інакше бот не зможе закомітити `data/recipes.json`.
3. Перед злиттям завжди переглядайте вкладку *Files changed*.

### Схема `data/recipes.json` (`schemaVersion: 1`)

Згенерований файл має таку структуру. `schemaVersion`, `device` і `categories` беруться з `data/meta.json`, а кожен елемент `recipes` — це вміст одного файлу `data/recipes/<id>.json` (рецепти відсортовані за назвою файлу).

```json
{
  "schemaVersion": 1,
  "device": "OL650EU",
  "categories": [{ "id": "main", "name": "Основні страви", "icon": "🍲" }],
  "recipes": [{
    "id": "plov",
    "title": "Плов",
    "category": "main",
    "description": "Короткий опис",
    "servings": 5,
    "prepMinutes": null,
    "cookMinutes": 80,
    "difficulty": null,
    "tags": ["свинина", "рис"],
    "ingredients": [
      { "name": "Рис", "amount": 500, "unit": "г", "note": "промити" },
      { "name": "Олія", "amount": 80, "amountMax": 100, "unit": "мл", "note": null },
      { "name": "Спеції", "amount": null, "unit": null, "note": null }
    ],
    "steps": [{
      "stage": "Етап 1. …",
      "text": "Що зробити",
      "mode": "Pressure Cook",
      "temperature": null,
      "pressure": "High (Hi)",
      "minutes": 20,
      "minutesMax": null,
      "valve": "SEAL",
      "note": "Додаткове пояснення",
      "verified": true
    }],
    "tips": ["Порада"],
    "image": "images/plov.svg"
  }]
}
```

| Поле | Опис |
|---|---|
| `categories[].id / name / icon` | Категорія. Категорії без рецептів показуються з позначкою «Незабаром». |
| `categories[].subtitle` | Необов'язковий підпис під заголовком сторінки категорії (наприклад, модель мультиварки). |
| `categories[].image` | Необов'язковий відносний шлях до SVG/PNG-значка категорії. Якщо задано, показується замість emoji з `icon`; `icon` лишається для випадних списків. |
| `servings` | Базова кількість порцій, від неї рахується перерахунок. `null` вимикає перемикач порцій. |
| `prepMinutes`, `cookMinutes` | Хвилини або `null`, якщо невідомо. |
| `difficulty` | `"easy"`, `"medium"`, `"hard"` або `null`. |
| `ingredients[].amount` / `amountMax` | Число або діапазон (`amountMax`). `null` означає «за смаком», таке не перераховується. Для `шт.` і `головка` округлення до ½. |
| `steps[].stage` | Необов'язкова назва етапу, кроки групуються за нею. |
| `steps[].mode` | Назва режиму з інструкції: `Pressure Cook`, `Sear/Sauté`, `Steam`, `Slow Cook`, `Air Fry`, `Steam Air Fry`, `Steam Bake`, `Steam Bread`, `Steam Meals`, `Grill`, `Bake`, `Dehydrate`, `Yogurt`; для скидання тиску — `Natural Release`. `null` означає крок без мультиварки. |
| `steps[].pressure` | Для `Pressure Cook`: `High (Hi)` або `Low (LO)`. |
| `steps[].temperature` | Температура в °C або рівень Sear/Sauté (`Lo 1` … `Hi 5`). |
| `steps[].minutes` / `minutesMax` | Час кроку або діапазон. |
| `steps[].valve` | `SEAL` або `VENT`. |
| `steps[].verified` | Внутрішня позначка для перевірки даних. На сторінці рецепта не відображається. |

Якщо змінюєте схему (нові обов'язкові поля, інша структура), збільште `schemaVersion`, оновіть `SUPPORTED_SCHEMA_VERSION` у `js/data.js` і цей розділ README.

## Оновлення версії кешу Service Worker

Service Worker кешує застосунок для офлайн-роботи. `data/recipes.json` завантажується з мережі в першу чергу (network-first), тому нові рецепти з'являються і без зміни версії кешу. Після **будь-якої** зміни HTML, CSS, JS, іконок або зображень:

1. Відкрийте `service-worker.js` і збільште версію: `const CACHE_VERSION = 'v3';` → `'v4'`.
2. Якщо додали або перейменували файл, оновіть список `APP_SHELL`.
3. Опублікуйте зміни. Під час активації нової версії старі кеші видаляються автоматично. Користувачі отримають оновлення після наступного відкриття застосунку, іноді для цього потрібно двічі перезавантажити сторінку.

## Публікація на GitHub Pages

1. Закомітьте й запуште зміни в гілку `main`.
2. На GitHub: **Settings → Pages → Build and deployment → Source: Deploy from a branch**, гілка `main`, папка `/ (root)`.
3. За хвилину-дві застосунок буде доступний за адресою `https://<ім'я-користувача>.github.io/CookBook/`.

Усі шляхи в проєкті відносні, тому застосунок працює як з підшляху, так і з кореня домену.

## Встановлення на телефон

- **Android (Chrome / Edge):** відкрийте сайт, у меню **⋮** виберіть **«Встановити застосунок»** або **«Додати на головний екран»**.
- **iPhone / iPad (Safari):** відкрийте сайт, натисніть **Поділитися** → **«На початковий екран»**.
- **Windows / macOS (Chrome / Edge):** значок встановлення в адресному рядку.

Після першого відкриття застосунок працює без інтернету.

## Відомі обмеження

- Обране, нещодавні, тема, позначки інгредієнтів і власні рецепти зберігаються в `localStorage` **лише на цьому пристрої й у цьому браузері**. Синхронізації немає. Якщо очистити дані сайту, вони зникнуть.
- Перерахунок порцій змінює лише список інгредієнтів. Кількість води й час у кроках наведено для базової кількості порцій. Збільшуючи кількість, стежте за лінією PRESSURE MAX і правилом «рис — не більше половини чаші».
- Час готування не враховує час набору тиску («PrE») і тривалість природного скидання понад вказане в рецепті.
- Screen Wake Lock підтримується не всіма браузерами (зокрема, старими версіями Safari). Там, де його немає, кнопка не показується.
- У Safari на iOS офлайн-кеш може бути очищений системою, якщо застосунком довго не користуватися.
